## Judgment calls
- **Bounded-DOM arithmetic: sound.** 16 panes × (8 BEHIND + 16 AHEAD) = 384 mounted articles worst case, versus unbounded growth today. The render slice bounds DOM regardless of loaded-section count. Residual, non-blocking: the `sections` data array and the measured-heights map still grow unboundedly in JS memory (identical to the full reader today); DOM is the binding constraint the MASTER caveat names, and it is bounded. The spacer-drift and jsdom-convergence risks are honestly registered.
- **16-cap deviation from "no 3-pane cap": justified and stated.** The design cites the owner's own 4x4 shape (order 2026-08-02 §3) and the parser-bound rationale already standing in desk.ts. A desk URL is user-editable input; an unbounded parser is not on the table. Consistent with the order's intent (the 3-cap is lifted; the grid is real).
- **The named trade — ADAPT ~100 lines, do not extract: ACCEPTED.** The reader's window math is genuinely entangled with the header line (`:141-142`), progress reporting (`:172`), pending-scroll restore, prepend anchor, and the chase loop (`:188-196`); extraction would put the most load-bearing reading surface in the blast radius of a desk change for marginal reuse. A sync-guard test between the two implementations is the wrong tool — the constants deliberately differ (12/28 vs 8/16), so it would pin internals, not contract. The shared behavioral contract (bounded mount count, convergence at zero-height rects) is what the new bounded-DOM test pins. Mitigation for the hand-maintained-copies defect class is a comment cross-reference, per condition 2.
- **File list: one genuine miss.** `web/test/components/desk-pane-continuous-read.test.tsx` pins exactly the machinery being replaced — the document-capture scroll auto-load, the "Read more" sentinel button with rect-proximity check, the in-flight dedupe, and the error-storm guard (its header documents the deep-audit HIGH). The design replaces that mechanism and never mentions this test. Condition 1.
- **Red-proof: present and correctly shaped** (RED against the current unbounded renderer with committed transcript, then GREEN, plus a seeded red-proof with the window bypassed). Meets THE_LOOP rule 4.

## Conditions
1. **Add `web/test/components/desk-pane-continuous-read.test.tsx` to the file list.** Its pinned behaviors must be re-expressed against the new mechanism, not deleted: proximity-driven prefetch (now via the window's prefetch trigger), load-failure keeps the sections already read, and no request storm on repeated scroll frames after an error. The hook's invariant test covers in-flight dedupe; the pane-level no-storm-on-error pin must be re-established, since the "always-near zeroed rect" failure mode it guards changes shape under windowing.
2. **Cross-reference the adapted window math.** When the pane window lands, both `desk-pane.tsx` and `work-reader.tsx` carry a comment naming the other as the adapted sibling (the repo's existing idiom for deliberate copies), so a fix to one window's chase/convergence logic is visibly owed to the other.
3. **Sweep all stale "three" language in `desk.ts`, not just the header.** Also stale at 16: `withPane`'s doc ("adds a fourth work from a full desk", :161-166), `decodeDeskReport`'s doc ("wastes one of three slots", :113; "yields three panes", :114), and the `DeskDecodeReport` A078 comment's cap description (:95). The desk page's "side by side" empty-state copy (:124) must also match the grid, as the design already intends.
4. **Fix the path slip in the design:** the hook's invariants live at `web/test/invariants/work-reader-paging.test.tsx`.
5. **Binding at build time:** red transcripts committed to `docs/evidence/swarm-2026-08-22/w-ux3/` before the GREEN run is claimed, and the bounded-DOM assertion pins an exact bound (≤ 24 mounted `article[id^="s"]` per pane) rather than a vague "small".
