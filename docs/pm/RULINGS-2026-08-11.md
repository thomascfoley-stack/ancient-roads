## 1. deps — the 8 better-auth GHSAs (the ONLY red audit leg)

**Topology, established from evidence 2026-08-11** (WO-3: code + both lockfiles + Vercel
production env, read-only): production runs **Neon Auth** — `@neondatabase/auth@0.4.2-beta`,
`createNeonAuth` proxying to Neon's **hosted** better-auth server (`NEON_AUTH_BASE_URL` /
`NEON_AUTH_JWKS_URL` / `NEON_AUTH_COOKIE_SECRET` live in the prod env). The 2026-08-05 direct
Better Auth 1.6.26 cutover was **reversed** (ADR-107/108, `dc87099`); `BETTER_AUTH_URL` /
`BETTER_AUTH_SECRET` linger in Vercel, read by no code (grep-verified). The only better-auth
in the tree is **1.4.18**, transitive under `@neondatabase/auth(-ui)`. **No newer release
exists**: 0.4.2-beta (2026-06-08) is the latest published. `package.json` and
`scripts/audit.sh` notes claiming the opposite were corrected 2026-08-11.

**Per-GHSA reachability.** The vulnerable code in every advisory is **server-side plugin
code**. This app runs no better-auth server — the server is Neon's hosted service — and a
grep of `web/src` (2026-08-11) finds **zero references** to any affected plugin:

| GHSA-fmh4-wcc4-5jm3 | high | organization plugin invitation acceptance | no |

**Recommendation:** ignore-with-rationale — all 8 ids into `pnpm.auditConfig.ignoreGhsas`
with a per-ID note in docs/SECURITY.md ("unreachable: provider-side plugin not enabled;
server executes on Neon's hosted service"), citing this page. The alternative is the
SEC-1-sequel migration off the beta — the direction ADR-107 already weighed and rejected
once; revisit only if Neon stalls.

**RULED 2026-08-11: accepted ("do what you suggest"), and LANDED the same day** — with one
mechanism refinement forced by the A7 sec1-upload-gate: GHSA-g38m must NOT enter
`ignoreGhsas` (A7's in-path set is exactly `{g38m}`; ignoring it would either arm the gate
against `MULTI_USER_UPLOADS` or empty the set and fail its non-vacuity check). So the
landed shape is: **6 ids in `ignoreGhsas`** (9h47, 86j7, 7w99, 392p, fmh4, pw9m — all
adjudicated "no / not in path" in docs/SECURITY.md's adjudication table, the three former
"assess" rows settled), and **2 ids declared `--expect-red` in scripts/audit.sh** —
`g38m` (closed by Verify at Sign-up 2026-08-08; the closure is a console toggle this repo
cannot observe, so it stays declared and visible) and `qq9h` (ADR-038 accepted-red; method
not shipped, hosted method config unobservable — kept visible, not ignored). Exact-match
semantics: an extra advisory or a disappearance from the declared set both fail the leg.

**What would settle it (any one):** Neon publishes `@neondatabase/auth` > 0.4.2-beta →
upgrade, no ruling needed; the app ever enables an OAuth-provider / mcp / organization /
magic-link plugin → the ignores die that day (same discipline as `sec1-upload-gate.test.ts`);
a PoC showing 1.4.18 *server* code executing in our bundle rather than on the hosted
service. **Residual, unobservable from this repo:** the hosted console's plugin config —
one console check by the owner closes it.

**Adjacent cleanup:** delete orphaned `BETTER_AUTH_URL` / `BETTER_AUTH_SECRET` from Vercel
(zero code references, grep 2026-08-11). Settles when `vercel env ls production` no longer
lists them and the deploy stays green.
