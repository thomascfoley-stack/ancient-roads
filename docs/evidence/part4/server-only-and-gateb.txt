## 2. The real (narrower) breakage, and the real fix

TRUE STATEMENT: any script importing the REAL teacher path (`deepinfra` / `teach` / `rerank`) under
tsx failed, because `server-only` was not installed. That is the two SoS verification scripts.

FIX (two parts, both needed):
  a. `server-only` added as a devDependency of `web` (pnpm). Resolves now.
  b. Installing it is NOT sufficient. The package's default entry THROWS by design
     ("This module cannot be imported from a Client Component module"); its non-throwing entry is
     behind the `react-server` export condition. Scripts must run with:

        npx tsx --conditions=react-server --env-file=.env.local src/scripts/<script>.mts

     Verified: without the flag -> "cannot be imported from a Client Component";
               with the flag    -> "deepinfra imports OK", and both SoS scripts run with no stub.
  Both SoS script headers now document the flag and why.

## 3. AN INCIDENT I CAUSED: my own test turned Gate B red

`npm run audit` failed:
    ✗ GATE B FAILED: 2 license/provenance violation(s):
      - 141: published source license "public-domain" not in allowed set
      - 142: published source license "public-domain" not in allowed set

Both rows were `qa-published-boundary-*` sources seeded by the test I wrote in this same phase.
ALLOWED_LICENSES is `['Public Domain','CC BY','CC BY-SA']`; I seeded `'public-domain'`. The test
necessarily seeds a PUBLISHED source, and its final case deliberately leaves it published — so a
run that aborted before teardown stranded a published row with a disallowed license and failed a
SHARED gate for the whole repo.

This is exactly the class of defect I flagged in the Phase-1 highlight tests earlier today (a test
poisoning shared state). I did the same thing, and worse: theirs leaked rows, mine leaked a gate
failure. Recorded rather than quietly fixed.

FIXES:
  - residue deleted (2 sources + dependents); verified 0 qa sources and 0 published rows with a
    disallowed/null license remain.
  - the seed now uses `'Public Domain'`, so even leaked residue cannot fail Gate B.
  - teardown is belt-and-braces: every step independent (one failure cannot skip the rest), the
    source forced OUT of 'published' before deletion, and the final sweep matches by slug PREFIX so
    it reaps rows leaked by earlier interrupted runs too.
  - re-verified: test 5/5 green, 0 residue, `npm run audit` PASSED — all gates green.

NOTE for the neighbours: `sections-unit-ordinal.test.ts` also seeds `'public-domain'`, but seeds
`status='staged'`, and Gate B only inspects PUBLISHED rows — so it is not currently exposed. It
would become exposed the moment that seed's status changed. Left as-is; noted here so the next
person does not have to rediscover why one is safe and the other was not.
