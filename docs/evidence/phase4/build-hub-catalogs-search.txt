## A PERFORMANCE DEFECT FOUND BY THE BROWSER PASS (and fixed)
The first search screenshot captured "Searching…" — the query had not returned. Measured:
    raw match count (no headline)          152ms   (27,738 matching sections for 'grace')
    dedupe + rank, NO ts_headline          219ms
    same WITH ts_headline inside          3781ms   (17x)
ts_headline re-parses the whole document and was being computed for EVERY match before the LIMIT
discarded them. Restructured to rank+page on cheap columns first, then join back and compute
snippets for only the <=100 returned rows.
  END-TO-END THROUGH THE REAL API, after:
    q=grace&catalog=sermons        200   954ms   (was ~4s)
    q=God (cross-corpus)           200  2827ms   (was 21s+ in-suite)
    q=faith&catalog=commentaries   200   632ms
  All 21 tests across the three suites still pass — the fix is a plan change, not a semantics change.
